Problem

Valve pressure testing at FlowSafe relied on physical dial gauges and manual, paper-based recordkeeping. Test results — including the three-pop and bubble-test procedures used to verify a valve — existed only as handwritten records tied to a single physical location, with no centralized digital record, no stored pressure trace, and no live visibility into what was happening on the test stands from outside the test area.

Why it mattered

Every test still required a technician to run the procedure, then separately transcribe results into paperwork that fed the Functional Test Report (FTR) and other downstream documentation. That duplication — testing, then documenting the test — consumed real technician and administrative time on every valve that shipped, and gave managers no way to see test-stand status without physically walking the floor.

Constraints

  • Had to work on the shop floor, integrated with existing physical digital pressure gauges rather than replacing them.
  • Had to preserve FlowSafe's existing test procedures (three-pop testing, bubble-test workflows) rather than change the underlying engineering process.
  • Had to support the existing Functional Test Report (FTR) output that downstream documentation depends on.
  • Full ERP integration was out of scope — the system needed to lay a read-only foundation for a future Epicor integration, not replace or write into Epicor.

My role

I developed the system as my project during my Industrial Engineering internship at FlowSafe / Dresser Utility Solutions — from the operator-station hardware and guided testing workflow through the centralized data model and the manager-facing dashboard.

Data & engineering approach

  • Raspberry Pi operator stations at the test stands, connected to the physical digital pressure gauges for live pressure capture during a test.
  • Guided, on-screen operator workflows that walk a technician through the correct testing sequence — including the three-pop and bubble-test procedures — instead of relying on memory or a paper checklist.
  • Every test tagged with operator, job, and valve identification, and its full pressure trace stored against a centralized test record rather than a handwritten sheet.
  • A manager-facing dashboard giving live visibility into test-stand status, independent of walking the floor.

Development process

I built the system incrementally on the shop floor: standing up an operator station and gauge integration first, then layering in the guided workflow, the centralized test-record database and pressure-trace storage, and the manager dashboard on top of that same data. Functional Test Report support and the read-only Epicor integration foundation were built to sit on the same central record, so the live test data, the FTR, and the future ERP link all trace back to one source instead of three separate, disconnected records.

Solution

The result is a connected pressure-testing ecosystem: operators run guided tests at Raspberry Pi stations wired to the physical digital gauges, every test is captured with its full pressure trace and operator/job/valve identification, and that record is centralized rather than sitting on paper. Managers get live visibility into test-stand activity, the Functional Test Report draws from the same recorded data, and the system has a read-only foundation in place for a future Epicor connection.
